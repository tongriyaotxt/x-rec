## 0. 一句话结论

X-Rec 把「召回」从**给用户算一个（或几个）确定向量**改成**在 item 的连续 embedding 空间里学一个条件分布 p(x|c)，用 flow matching 一次性生成 K 个触发向量再去 ANN 检索**——它同时避开了 U2I 的 delta 分布表达力上限、SID-AR 的量化误差与逐 token 解码。

线上结果（TikTok 某一垂类内容，两次放量）：

| 指标 | V1（无 anchor） | V2（+anchor） | 合计 |
|---|---|---|---|
| 垂类互动（Vertical Engagement） | +2.3779% | +1.7705% | **+4.1484%** |
| 大盘互动（General Engagement） | 不显著 | +0.0111% | +0.0111% |

离线（47 个流式分区的均值，Recall@20）：

| 方法 | 范式 | Recall@20 | 生成吞吐 QPS |
|---|---|---|---|
| **X-Rec** | 连续空间 FM | **10.76%** | **575.7** |
| X-Rec-AR（同 backbone 的 SID-AR 对照组） | 离散自回归 | 10.23% | 166.4 |
| X-Rec-U2I（同 backbone 的单向量对照） | 双塔 | 6.98% | — |
| LATTE | SID-AR | 6.83% | — |
| LLaDARec | 离散扩散 SID | 6.53% | — |
| TIGER | SID-AR | 5.21% | — |
| EAGER | SID-AR | 4.93% | — |
| DreamRec | 扩散（单向量） | 4.30% | — |
| LRURec | U2I | 1.19% | — |
| SASRec | U2I | 1.03% | — |

**3.46×** = 575.7 / 166.4，质量还高 0.53 pp（38/47 个分区胜出）。

> **本地实跑的一句提醒**：以上全部是论文数字。本仓库的独立实现只能验证**机制**，不能验证**质量**——
> 合成基准上所有学习型变体都低于「返回最热 20 个 item」这个基线（3.93%），而 SID-AR 对照在本尺度会
> 崩塌成热度先验（4096 个请求只吐出 23 个不同 item）。原因与适用边界见 §5.3.1 与 §5.5。

## 1. 定位：它替换的是召回层的哪一段

推荐被写成「下一个 item 生成」：建模 `p(x | c)`，`c = (s, f)`，`s` 是按时间排序的行为序列，`f` 是期望目标属性（如「要预测的互动类型」）。每个历史交互是元组 `i_n = (x_n, f_n)`。

| 范式 | x 的表示 | p(x\|c) 的形式 | 时间 | 空间 |
|---|---|---|---|---|
| U2I | 连续 embedding | 训练：采样 categorical（InfoNCE）；推理：delta | O(N²) | O(1) |
| SID-AR | 语义 ID 序列 | 离散 categorical，自回归分解 | O(N(N+KM)) | O(LN) |
| **X-Rec** | 连续 embedding | 连续分布（FM 生成） | O(N(N+K))（L′=1, T=L） | O(N) |

（论文 Table 1；N=条件长度，K=触发数，M=SID 长度，L=层数，d=隐维）

### U2I 的死点（eq.2–4）

InfoNCE 的分母只在负样本集上归一化，是对全库 softmax 的**有偏采样近似**；推理时

```
p_u2i(x|c) = 1  if x^(e) = e_θ(c) else 0        # 一个点测度
```

即把多峰兴趣压成**一个 delta**。ComiRec 之类的多兴趣版本只是把 delta 的个数从 1 改成 K，本质没变，且 K 是超参、无法自适应兴趣峰的个数。论文用 VC 维给了一个理论注脚：K 个触发对应 K 个半空间的并，VC 维是 Θ(dK log K)——**触发数增加直接提高可表达决策边界的复杂度**。

### SID-AR 的两个死点（eq.7–9）

1. **flawed SID**：连续 embedding 量化成 RQ 码必然有量化误差；且要求 SID 与 itemID 近似一一对应，工业规模下做不到（常见补丁是末尾加非语义 hash token，又破坏了语义结构）。
2. **低吞吐**：逐 token 解码 + KV cache 维护，复杂度里多出 `O(NKM)` 项和 `O(L(N+M))` 的显存。

### X-Rec 的取舍

直接在连续空间建模，复杂度落在两者之间（`O(N(N+K))`），**表达力对齐 SID-AR，吞吐对齐 U2I 一侧**。

## 2. 原理（机制层）

### 2.1 Flow matching 骨架（eq.14–18）

学一个时变流 `φ_t(·|c)`，把基分布 `ε ~ r(ε)` 搬到目标分布：

```
φ_0(ε|c) = ε,    φ_1(ε|c) ~ p_data(x^(e)|c)
```

条件流用插值构造，回归其导数（条件速度场）：

```
L_FM = E[ || v_θ^t(x̄_t^(e) | c) − d/dt x̄_t^(e) ||² ]
```

只要回归到最优速度场，诱导的 ODE `dx̃_t/dt = v*_θ(x̃_t|c)` 的解就满足上面的搬运要求。

### 2.2 球面几何：为什么必须是 RFM（eq.20–22）

item embedding 是**对比学习 + L2 归一化**得到的，天然落在单位超球 `S^{d_e−1}` 上。欧氏直线插值 `(1−t)ε + t x̂` 在 t=0.5 时模长只剩 0.42（本仓库 `rfm.py --selftest` 实测），中间态全部离开流形，模型被迫同时学「往目标走」和「回到球面」两件事。

RFM 改用**测地线插值**：

```
x̄_t = sin((1−t)ω)/sinω · ε + sin(tω)/sinω · x̂ ,   ω = arccos(εᵀx̂)
```

对应速度场（对 t 求导）：

```
d/dt x̄_t = ω/sinω · ( cos(tω)·x̂ − cos((1−t)ω)·ε )
```

> 注：pdftotext 抽取 eq.21 时把 `cos(tω)` 和分母 `sinω` 排版错位，容易被误读成 `ω/cos(tω)`。
> 本实现取的是对测地线求导的标准形式，`rfm.py` 里用有限差分验证到 **3.0e-4**，可以确认公式选取。

损失（eq.22）就是把上面的解析速度当回归目标；训练时每个样本采样多个 ε 和 t，取经验均值。

### 2.3 Anchor conditioning：把「生成」拆成「选区域 + 精修」

直接生成 128 维细粒度 embedding 太难（空间多峰、结构复杂）。X-Rec 先预测目标 embedding 所属的**粗语义区域** `x^(a) ∈ A`（簇心索引），再以它为条件生成：

```
L_anchor = −E[ log p_θ(x^(a) | c) ]                      # eq.19, 交叉熵
L = α·L_anchor + β·L_RFM ,  α = 0.1, β = 1                # eq.23
```

三个收益：

1. **降难度**：生成问题从「在整个球面上找点」变成「在指定区域内找点」，Recall@20 提升 **2.05 pp**（10.76 → 8.71，去掉 AC）。
2. **可解释的正确性**：把生成触发量化回 SID 看第一位命中率，41.37% vs 28.57%（top-20），说明 AC 真的提升了「粗区域选对」的能力。
3. **多样性旋钮**：`p_θ(x^(a)|c)` 的采样温度直接控制触发覆盖面。温度→0 退化成 delta（窄而深），温度→∞ 变均匀（宽而散）。实测 0.8→1.6 时两两余弦从 0.809 单调降到 0.779，Recall@20 从 10.38% 升到 10.84%，默认取 1.4（接近饱和点）。

anchor 预测器就是一个 softmax 分类头（eq.29），输入是序列末位隐状态 + 目标属性投影之和：

```
p_θ(x^(a)|c) = softmax_a( w_aᵀ ( i_N^(h_L) + f^(m) ) )
```

### 2.4 Late-interaction DiT：每步只跑最后一层

标准 DiT 每个去噪步都要把「条件 token + 去噪 token」整体过一遍 L 层。X-Rec 的做法：

- 条件序列 `s^(m)` 过前 L−1 层（causal mask），得到 `s^(h_{L−1})`；
- 最后一层的 K/V 只从 `s^(h_{L−1})` 算**一次**并缓存；
- 每个去噪步：只把去噪 token 送进**第 L 层**，与缓存的 (N+1) 个 key 做注意力，输出经 `W_v` 投到 d_e，再**投影到切空间**：

```
v' = W_v ĩ_t^(h_L)
v  = v' − (v'ᵀx̃_t)·x̃_t          # eq.31，落在 T_{x̃} S^{d_e−1}
```

代价与收益：

| 配置 | 每步层数 L′ | 步数 T | Recall@20 | QPS | 相对 1 层 |
|---|---|---|---|---|---|
| late-interaction | 1 | 30 | 10.76% | **575.7** | 1.00× |
| 全层去噪 | 7 | 30 | 11.59% | 218.6 | 2.63× 慢 |
| 全层去噪 | 14 | 30 | 11.94% | 127.8 | 4.50× 慢 |
| 全层去噪 | 28 | 30 | 11.81% | 69.5 | 8.28× 慢 |
| X-Rec-AR | — | 4 token×20 beam | 10.23% | 166.4 | 3.46× 慢（vs 1 层） |

结论：**14 层换来 +1.18 pp，代价是 4.5 倍吞吐**——线上选 1 层。注意层数加到 28 反而比 14 差（11.81 vs 11.94），说明「更深不等于更好」。

### 2.5 训练流程（§3.4）

**Stage 1 预训练**：对每条行为序列做自回归分解 `∏ p_θ(x_n | i_{1:n−1}, f_n)`（eq.32），目标是学通用的 item 转移规律。工程技巧：用前缀对角 mask（Figure 3a），一次 prefill 并行算出序列里所有位置的损失——每个去噪 token 只能看自己的前缀、彼此互不可见，位置编码取「前缀长度+1」。

**Stage 2 SFT**：把上下文换成线上真实的召回事件上下文——「长期正向序列 + 最近交互序列」（前者稳定偏好，后者即时意图）。每个目标采 8 个独立噪声/时间步，用 target diagonal mask（Figure 3b）让 8 份副本并行训练且互不泄漏，位置索引统一为「条件长度+1」。

**CFG 准备**：训练时以 5% 概率丢弃条件，使模型能估边缘速度场，推理时

```
v = v_uncond + λ·(v_cond − v_uncond),  λ = 3.0
```

### 2.6 推理（§3.2.2）

```
1. 编码上下文 → anchor logits → 按温度 1.4 采样 K=20 个 anchor
2. x̃_0 ~ U(S^{d_e−1})（球面均匀噪声）
3. for t in 0..1, Δt=1/30:
       v = CFG( v_θ(x̃_t | c, anchor),  λ=3.0 )
       x̃_{t+Δt} = cos(‖v‖Δt)·x̃_t + sin(‖v‖Δt)·(v/‖v‖)     # eq.24，Riemannian Euler
4. 末态 x̃_1 即触发向量，送 ANN 取 top-R
```

Euler 步用**指数映射**而非 `x + vΔt`，所以任意步长都严格留在球面上（本仓库实测 200 步后模长偏差 3.6e-6）。

### 2.7 为什么是 flow matching，而不是 DDPM / 自回归

| 维度 | DDPM（如 DreamRec） | SID-AR（TIGER/OneRec） | X-Rec（RFM） |
|---|---|---|---|
| 需不需要模拟采样过程来训练 | 不需要，但噪声表要调 | 不需要 | 不需要（simulation-free，直接回归解析速度） |
| 采样步数 | 数百～千步（可用 DDIM 降） | M 步串行（M=SID 长度） | 30 步，可蒸馏 |
| 轨迹形状 | 随机扩散，弯曲 | — | 测地线，近似直线，**适合少步积分** |
| 流形约束 | 需 variance-preserving 变体 | 无（离散码本） | 闭式解：测地线 + 切空间投影 |
| 误差来源 | 离散化误差 | 量化误差 + 码本映射失败 | 仅数值积分误差（30 步足够） |

关键在最后两行：球面上的测地线有闭式解（`sin((1−t)ω)/sinω` 那一套），所以「在球面上做 FM」不需要任何近似几何，而 DDPM 在球面上通常得换用特定的 VP-SDE 或投影步。再叠加 anchor 把「在整球面上采样」压成「在指定区域采样」，步数才能压到 30。

### 2.8 在生成式召回谱系里的位置

```
双塔 U2I (YouTube DNN, SASRec, ComiRec)
        └─ 生成式检索 TIGER (2023, SID + AR)
                ├─ OneRec / OneRec-V2 (字节, 2025, 统一召回+排序 + 迭代偏好对齐)
                ├─ LLaDA-Rec / MaskGR / LATTE (2025-26, 离散扩散并行生成 SID)
                └─ X-Rec (2026, 连续空间 FM 生成 embedding 触发)
HSTU (Meta, 2024) —— 另一条路：不做"生成 item"，用 trillion-scale 序列 transducer 直接出排序分
```

X-Rec 的位置很清晰：**承认「生成式」这条路线，但把生成对象从「离散 ID 序列」换回「连续 embedding」**，从而同时甩掉量化误差和逐 token 解码。这也是它与 LLaDA-Rec（同为「并行生成」但仍在 SID 空间）的核心分歧——X-Rec 的消融里，把 SFT 目标换成 SID 重建向量会掉 2.13 pp，量化损失是实打实的。

## 3. 实验设置与数字（论文）

**数据**：TikTok 工业流式基准，47 个连续分区，每区 2.6M 训练 / 10K 测试；预训练序列 ≤200 交互。评测协议是**流式**的——第 i 个分区的最终 checkpoint 作为第 i+1 个分区的初始化，逼近线上的持续更新。

**指标**：`Recall@(K×R)` = 目标是否落在 K 个触发各自 top-R 的**并集**里；默认 20×1。

**实现**：Qwen3-0.6B 做 backbone（去掉 token embedding 后 0.46B 参数）；item = 128 维多模态 embedding（单位球）；SID = RQ 4 码本 × 4096，重建余弦 0.94。预训练 1 epoch / 200K step / batch 4096 / lr 5e-4（2K warmup，cosine 降到 1e-4）；SFT 3 epoch / lr 1e-4 常数 / batch 512。

**消融汇总**：

| 变体 | Recall@20 | 变化 |
|---|---|---|
| X-Rec | 10.76% | — |
| w/o anchor conditioning | 8.71% | −2.05 pp |
| w/o RFM（换欧氏 rectified FM） | 8.98% | −1.78 pp |
| w/o 预训练 | 5.49% | **−5.27 pp** |
| SFT 目标换成 SID 重建向量 | — | −2.13 pp（R@20）/ −2.38 pp（R@50） |

预训练是最大单项，说明「转移规律」不是靠下游 SFT 就能补回来的。

**广度 vs 深度**（固定 20 个候选预算）：

| 配置 | 1×20 | 5×4 | 10×2 | 20×1 |
|---|---|---|---|---|
| X-Rec | 8.28% | 8.60% | 9.63% | 10.76% |
| X-Rec-U2I-K | 6.98% | — | 5.32% | — |
| 两两余弦（X-Rec） | 1.00 | — | 0.823 | 0.783 |

X-Rec 把预算铺宽就涨；U2I-K 铺宽反而掉 1.66 pp——它的「分散」是表面的（余弦 0.696 更低但召回更差），因为只有被选中的那一个兴趣向量在训练时收到梯度。

**Case study**：用户历史落在 Cars/Trucks/Motorcycles 与 Cooking 两峰，X-Rec 的触发点在流形上覆盖两峰，最近余弦 0.942；X-Rec-U2I-5 的 5 个触发塌在**两峰之间的谷底**，最近余弦只有 0.199。

### 4.3 三条复现路线

**路线 A：机制验证（已在本仓库跑通，1M 参数 / CPU / ~80 s）**

```
python rfm.py --selftest        # 公式对不对
python train.py --sweep         # 两个阶段 + 温度扫描
python bench.py                 # late vs full-layer
```

**路线 B：公开数据集上的可比较实现（1–2 天）**

1. item 向量：Amazon/ML-1M 用 BERT/CLIP 特征 → L2 归一化（**这是硬前提**，RFM 的球面几何依赖它）；
2. anchor：对 item 向量跑 K-means（或 RQ 第一层码本），anchor 数取 4096 级；
3. backbone：Qwen3-0.6B / 自建 12 层 Transformer，改成「前 L−1 层过条件 + 第 L 层算速度」；
4. 训练：pretrain（全库序列，随机前缀）+ SFT（目标事件上下文，8 噪声副本）；
5. 检索：faiss `IndexFlatIP`（内积 = 余弦，因为都已归一化）；
6. 对照组：SASRec（U2I）、TIGER/MiniOneRec（SID-AR）。这样得到的 `Recall@20` 才和论文表可比。

**路线 C：生产替换召回源（1–2 个月）**

- 离线：多模态 item 向量日更 → anchor 词典重建 → 按 anchor 分片建 ANN；
- 在线：请求进来先 prefill（前 L−1 层，缓存第 L 层 K/V）→ CFG 双分支（条件 / 无条件）→ 30 步 Euler → K 个触发并发查 ANN → 与现有双塔召回并集去重；
- 尾延迟主要来自 30 步串联，优先做：少步蒸馏、自适应步长、把 CFG 两分支合批。

### 5.2 吞吐（`bench.py`）

同一组权重、同一批请求，只改「每步跑几层」：

| 配置 | ms/请求 | QPS | 相对 1 层 |
|---|---|---|---|
| late-interaction，L=3 | 4.08 | 245.1 | 1.00× |
| 全层去噪，L=3 | 5.41 | 184.7 | 1.33× 慢 |
| late-interaction，L=12 | 5.63 | 177.6 | 1.00× |
| 全层去噪，L=12 | 15.43 | 64.8 | **2.74× 慢** |

规律：**收益随层数增长**。按论文尺寸（d=1024, L=28, N=199, K=20, T=30）做解析成本模型：

| 路径 | GMAC/请求 | 串行步数 |
|---|---|---|
| X-Rec（late interaction） | 77.7 | 30 |
| X-Rec（全层去噪，28 层/步） | 290.9 | 30 |
| SID-AR（beam 20 × 4 token） | 73.5 | **80** |

注意最后一列：SID-AR 的**算力并不比 X-Rec 高**（73.5 vs 77.7 GMAC），它输在 **80 个串行步**——每步只有 1 个 token 的工作量，GPU 占用率极低。论文的 3.46× 本质是**延迟/占用率**收益，不是 FLOP 收益。这一点对自建系统很重要：如果你已经有一个高并发、大 batch 的 AR 解码器，收益会被摊薄；如果你的瓶颈是单请求尾延迟，收益立刻显现。

| U2I（双塔单向量） | 0.02% [0.00–0.02] | 0.71% [0.59–0.83] | 91.0% | 1.000 | 0.04 |
| U2I-K（ComiRec-SA，K=20） | 0.07% [0.02–0.12] | 0.90% [0.81–0.98] | 96.2% | 0.972 | 0.04 |

**跨 3 seed 仍然成立的**：

1. **预训练是最大单项**：0.88% → 0.44%（掉 50%），且是唯一区间不重叠的对比（[0.85–0.90] vs [0.42–0.46]）。
   论文同样是最大单项（10.76 → 5.49，掉 49%）。
2. **同预算下 X-Rec 优于双塔**：1×20 侧 1.13% vs 0.71%；20×1 侧 0.88% vs 0.02%。
3. **多兴趣 U2I 是假分散**：U2I-K 的 20 个兴趣向量两两余弦 **0.972**，20×1 只有 0.07%——
   铺宽预算没有收益。论文口径是「U2I-K 余弦 0.696 更低但召回 5.32% 更差」，机制相同。

**加了种子之后不再成立的**（上一版是单 seed，结论写过头了）：

1. **anchor conditioning 的单项增益**：0.81% [0.56–1.15] 与 0.88% [0.85–0.90] 重叠，方向都不稳。
   上一版单 seed 报的是 0.68%，属于抽到了低端种子。
2. **RFM 的单项增益**：0.68% [0.44–0.88]，重叠。
3. **all-prefix mask**：0.91% vs 0.88%，旧路径甚至略高（重叠）——Fig.3(a) 的实现在 `model.py:loss_all_prefix`，
   但在 6000 item / 300 step 的预算下没有可测收益，照实记录。
4. `1×20 > 20×1`（1.13% vs 0.88%）与论文相反，原因仍是库规模与头部密度，见上一版的解释，未变。

**温度扫描**（单 seed，n_eval=4096）：0.8→0.81%、1.0→0.88%、1.2→0.90%、1.4→0.90%、1.8→0.90%。
合成世界里温度基本平坦（论文默认 1.4 不在最优点也差不了多少），说明 32 个 anchor 的粗粒度下
温度这个旋钮几乎不起作用；4096 个 anchor 的工业设置里它才承担「覆盖 vs 精度」的调节。

### 5.3.1 校准：这些绝对数字到底处于什么位置

`baselines.py` 给出的三个参照点（同 20 个候选、同一测试集）：

| 参照 | Recall@20 | 含义 |
|---|---|---|
| 均匀 | 0.33% | 地板 |
| **热度@20**（训练集最高频的 20 个 item，所有请求返回同一份） | **3.93%** | 任何个性化都得先超过它 |
| 模式内热度@20（用户**真实**目标模式内最高频的 20 个） | **14.53%** | 仍然忽略用户其余信息的粗上界 |

结论很硬：**本合成基准上，所有学习型变体都低于热度基线**。所以 5.3 的表只能读作
「同协议下的相对排序」，不能读作「这个方法能打」。

X-Rec 的模式覆盖 99% 说明触发确实落在正确兴趣簇里，但簇内排序不行：0.88% 离 14.53% 的模式内上界差 16 倍。
机制解释：合成世界里 item 的热度只编码在「距簇心的半径」上（头部 item 半径小），而 RFM 训练目标
是回归目标 item 的向量方向，模型学到了「落在哪个簇」，没学到「落在簇内哪个半径」。论文里这一步由
真实内容塔的语义密度承担（头部内容周围天然挤满近似样本），合成世界没有这个信号。

### 5.5 SID-AR 实体对照：为什么不等于「离散打败连续」

| 指标 | X-Rec | SID-AR |
|---|---|---|
| Recall@20（20×1，3 seed） | 0.88% | 2.80% |
| 解码实测（K=20，N=48） | 4.71 ms/请求（T=8 步） | 1.27 ms/请求（M=4 层） |
| 返回过的不同 item 数（4096 请求） | **3680** | **23** |
| 返回 item 的平均热度分位（1=头部） | 0.746 | 0.986 |
| 落在全局 top-20 的比例 | 5.7% | **56.8%** |

SID-AR 的 2.80% 是 **beam 崩塌**：4096 个请求只吐出 23 个不同 item，一半以上是全局头部，
本质是在背热度先验，所以它的召回（2.8%）刚好贴着热度基线（3.93%）下方。X-Rec 的召回更低，
但它真的在按用户出不同候选（3680 个）。

量化器本身是对的：4×256 残差量化在 6000 item 上重建余弦 **0.938**（论文 0.94），SID 唯一率 86.8%；
换成更粗的 2×64（码空间 4096 < 6000，唯一率 11.4%，重建 0.908）后召回 2.77%——**几乎不变**，
说明崩塌与量化粒度无关，是训练预算/目标函数的问题（300 步 teacher forcing 只够学到 unigram 先验）。

结论要写清：这是**本尺度 + 本预算**的结论，不是对论文 §A.2 的反驳。十亿级库里 SID 被大量 item 共享，
背不出来；论文的 10.23% 与 10.76% 是那个 regime 下的数。

## 6. 工程落地 checklist

| 环节 | 必须满足 | 不满足的后果 |
|---|---|---|
| item 向量 | L2 归一化、版本化、可重建 | RFM 的球面假设失效，速度场把点推出流形 |
| anchor 词典 | 与 ANN 分片键一致；定期重建 | 触发落在空簇 → 召回黑洞 |
| 上下文 | 长正向序列 + 最近交互序列拼接 | 只有长期偏好，即时意图丢失（论文 SFT 的核心） |
| 预训练 | 全库行为序列，随机前缀 | 论文实测掉 5.27 pp，是最大单项 |
| CFG | 5% 条件丢弃 + 推理 λ=3.0 | 无法做引导，多样性/相关性不可调 |
| 步数 | 30 步起步，可蒸馏到更少 | 尾延迟直接乘步数 |
| 触发数 K | 20（与现有候选预算对齐） | K 与 R 的分配决定广度/深度 |
| 监控 | 触发两两余弦、anchor 分布熵、空簇率、覆盖率 | 静默退化：召回数没变但覆盖变窄 |
| 评测 | 热度 / 均匀 / 模式内上界基线 + ≥3 seed + 候选预算对齐 | 分不清「模型学会了」还是「背了热度先验」；单 seed 会把噪声当收益 |

**风险**：① 双分支 CFG ≈ 2× forward，需要合批；② 30 步串联放大尾延迟；③ item 上新/下架导致的 embedding 漂移要触发 anchor + 索引重建；④ 论文只报了一个垂类的线上收益（+4.1484%），大盘 +0.0111%——**这是「新增一路召回源」的收益，不是「替换主召回」的收益**，不要按前者做容量规划。

## 8. 疑点与待验证

1. **论文内部数字不一致**：§4.3.3 说 14 层比 1 层「只高 1.05 pp」，但 11.94 − 10.76 = **1.18 pp**；1.05 反而等于 11.81（28 层）− 10.76。疑似笔误。QPS 比值（2.63/4.50/8.28）与图中数字自洽。
2. **线上收益归因**：V1（无 AC）+ V2（+AC）合计 +4.1484%，是「新增一路垂类召回源」的增量，不含替换成本；大盘 +0.0111% 说明对主 Feed 影响很小。
3. **SID vs 连续空间的质量对比依赖于 SID 构造**：论文的 SID-AR 对照组用的是自己 4×4096 的 RQ（重建余弦 0.94）。若把 SID 换成更好的构造（如 FORGE 等），10.23% 这个数会变，结论的「打平」是条件性的。
4. **anchor 数没做敏感性分析**：\|A\| 从 32 到 4096 对 Recall 的影响未给出，而这直接决定粗到细的粒度。
5. **T=30 的步数没有消融**：只有「层数 L′」的消融，没有「步数 T」的曲线；未来工作里也承认需要 few-step 蒸馏。
6. **CFG 的成本没计入吞吐**：575.7 QPS 是否含无条件分支（理论上是 2× forward）论文未说明。
7. **合成的多峰是「簇」，真实兴趣流形未必是**；论文的 t-SNE 图（AI 生成视频替代真实样本）只能定性佐证。
8. **离线表里没有热度基线**：10.76% / 10.23% 这些数的绝对水平无法判断——没有 popularity、没有随机、
   没有「同预算」说明。本仓库补上后才发现，合成基准上学习型模型全都打不过热度（§5.3.1），这类基线在
   召回论文里应当是默认项。
9. **SID-AR 对照没有报解码多样性**：0.53 pp 的差距（10.76 vs 10.23）在 beam search 崩塌时极易翻转。
   本仓库的实体对照在 300 步训练后只吐出 23 个不同 item（§5.5）——同一个模型换成有限预算就会从
   「接近打平」变成「被热度基线打败」。因此「离散 vs 连续」的结论必须绑定 beam 多样性/训练预算一起报。
10. **合成基准的 SID 唯一率**：6000 item / 4×256 RQ 下 86.8% 的 item 有唯一 SID，这已经接近「分类」
    而不是「生成」；论文十亿级库里 SID 必须被大量 item 共享，两者不是同一个任务。
