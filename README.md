# xrec-ref — a from-scratch reference implementation of X-Rec (continuous-space generative retrieval)

Unofficial, **mechanism-level** reimplementation of *X-Rec Technical Report* (ByteDance / TikTok,
[arXiv:2609.29180](https://arxiv.org/abs/2609.29180)): recommendation as conditional generation in the
**continuous item-embedding space** via **Riemannian flow matching**, with **anchor conditioning** and a
**late-interaction diffusion Transformer**.

It trains, evaluates, indexes and serves on one machine (CPU or a single GPU) in minutes, and it answers
one question honestly: *which of the paper's three ideas survive an independent implementation, and
which of its numbers are scale-bound?* It does **not** reproduce the paper's headline numbers — see
[What this is not](#what-this-is-not) and [Calibration](#4-calibration-what-the-absolute-numbers-mean).

> 中文完整研究笔记（机制推导、论文全部数字、开源生态盘点、B/C 交付清单、落地 checklist）：
> [`docs/x-rec-research-zh.md`](docs/x-rec-research-zh.md)。

```
rfm.py        geodesic interpolation, conditional velocity, tangent projection, Riemannian Euler, CFG
model.py      anchor predictor + late-interaction DiT velocity field, all-prefix pretraining mask
models_sid.py SID-AR control: residual-quantised semantic IDs, autoregressive decode (paper A.2)
sid.py        residual k-means quantiser (recon cosine 0.938 vs the paper's 0.94)
data.py       synthetic multi-mode interest stream, K-means anchors, Recall@(K x R)
dataset.py    real interaction log -> PPMI/SVD item vectors -> anchors -> leave-one-out splits
index.py      dependency-free IVF ANN (build/save/load/search, recall-vs-QPS sweep)
baselines.py  popularity / oracle-mode / uniform reference points + retrieval-profile diagnostics
train.py      two-stage training (all-prefix pretrain -> streaming SFT), ablations, checkpointing
serve.py      HTTP retrieval service: checkpoint -> K triggers -> ANN -> ranked ids
bench.py      late-interaction vs full-layer denoising, X-Rec vs SID-AR decode, ANN, analytic cost
```

## Quickstart

```bash
pip install -r requirements.txt

python xrec_ref/rfm.py --selftest                       # 6 numerical identities, no training
pytest -q                                               # 41 tests incl. ANN, data path, serving
python xrec_ref/train.py --out runs/xrec.json --sweep --ckpt-out runs/xrec.pt
python xrec_ref/dataset.py --fixture data/fixture.dat   # a log in MovieLens format
python xrec_ref/train.py --data data/fixture.dat --out runs/xrec_data.json
python xrec_ref/serve.py --ckpt runs/xrec.pt --self-test
python xrec_ref/bench.py                                # model + decode + ANN + analytic cost
python scripts/run_experiments.py --seeds 0 1 2          # the table below, ~15 min
```

Every number in this file is regenerated by `scripts/reproduce.ps1` plus its bash twin in the same
directory. Run everything **from the repo root**: the modules import each other flat
(`from rfm import ...`), so there is no `pip install .` step and `pyproject.toml` only holds the
pytest/ruff configuration.

## What it validates

**(1) The RFM math is implemented exactly** (`rfm.py --selftest`):

| check | result |
|---|---|
| geodesic endpoints `interp(0)=eps`, `interp(1)=x_hat` | exact |
| analytic velocity vs finite difference of the geodesic | 3.0e-4 |
| intermediate states stay on the sphere | 6.0e-8 |
| predicted velocity has no radial component | 5.2e-8 |
| Euler(200) reproduces `x_hat` | 2.3e-6 |
| Euclidean linear interpolation leaves the sphere | 0.42 |

**(2) Late interaction really is cheaper, and the gap scales with depth** (`bench.py`):

| config | ms/request | QPS | vs 1-layer |
|---|---|---|---|
| late-interaction, L=3 | 4.08 | 245.1 | 1.00x |
| full-layer denoising, L=3 | 5.41 | 184.7 | 1.33x slower |
| late-interaction, L=12 | 5.63 | 177.6 | 1.00x |
| full-layer denoising, L=12 | 15.43 | 64.8 | **2.74x slower** |

At the paper's shapes (d=1024, L=28, N=199, K=20, T=30) the analytic cost model gives 77.7 GMAC for
X-Rec vs 290.9 GMAC for full-layer denoising, while SID-AR costs 73.5 GMAC over **80 serial steps** —
i.e. the paper's 3.46x is a latency/occupancy effect, not a FLOP effect.

**(3) Ablations and controls, 3 seeds, mean[min-max]** (`scripts/run_experiments.py`, n_eval=4096,
candidate budget = 20 in every row):

| variant | Recall@20x1 | Recall@1x20 | mode coverage | pairwise cos | ms/request |
|---|---|---|---|---|---|
| **X-Rec** | **0.88%** [0.85-0.90] | **1.13%** [0.98-1.34] | 99.0% | 0.197 | 0.34 |
| w/o anchor conditioning | 0.81% [0.56-1.15] | 0.83% [0.76-0.98] | 99.3% | 0.163 | 0.33 |
| w/o RFM (Euclidean rectified FM) | 0.68% [0.44-0.88] | 0.85% [0.73-0.98] | 99.3% | 0.162 | 0.33 |
| w/o pretraining | 0.44% [0.42-0.46] | 0.44% [0.34-0.59] | 97.1% | 0.249 | 0.32 |
| legacy random-prefix pretraining | 0.91% [0.85-0.98] | 1.18% [0.88-1.37] | 99.7% | 0.234 | 0.32 |
| U2I (single vector) | 0.02% [0.00-0.02] | 0.71% [0.59-0.83] | 91.0% | 1.000 | 0.04 |
| U2I-K (ComiRec-SA, K=20) | 0.07% [0.02-0.12] | 0.90% [0.81-0.98] | 96.2% | 0.972 | 0.04 |
| SID-AR (4x256 RQ) | 2.80% [2.47-3.03] | 1.58% [1.56-1.59] | 100% | 0.146 | 0.10 |

U2I has one vector, so its 20x1 row is that vector repeated 20 times (equivalent to one trigger), and
U2I-K's 20 interest vectors sit at pairwise cosine 0.972 — i.e. "multi-interest" without diversity.

What survives: **pretraining is the dominant factor** (0.88% -> 0.44%, the only gap that is stable across
seeds), X-Rec beats both U2I controls at the same budget, and multi-interest U2I remains *superficially*
diverse (pairwise cosine 0.972) exactly as the paper argues. What does **not** survive: the single gain of
anchor conditioning (0.81% +- 0.30) and of RFM (0.68% +- 0.22) are inside the seed noise at this scale,
and the Fig.3(a) all-prefix mask gives no measurable gain over the legacy random-prefix recipe (0.88% vs
0.91%). The SID-AR row must not be read as "discrete beats continuous" — see the next section.

## (4) Calibration: what the absolute numbers mean

Two reference points at the same 20-candidate budget (`baselines.py`, `scripts/diagnose_prior.py`):

| reference | Recall@20 | note |
|---|---|---|
| uniform | 0.33% | floor |
| **popularity@20** (top-20 training items, same list for every request) | **3.93%** | any personalisation must beat this |
| oracle-mode popularity@20 (top-20 *within the user's true interest mode*) | **14.53%** | upper bound that still ignores the user |

So on this fixture **every learned variant is below the trivial popularity baseline**, and X-Rec's 99%
mode coverage only says that the triggers land in the right interest cluster — not that they rank items
well inside it. `scripts/diagnose_prior.py` shows what is actually happening:

| variant | Recall@20x1 | mean popularity percentile of returned items | share of returned items in the global top-20 | distinct items returned |
|---|---|---|---|---|
| X-Rec | 1.17% | 0.746 | 5.7% | **3680** |
| SID-AR | 1.46% | 0.986 | 56.8% | **23** |

SID-AR's apparent win is **beam collapse**: across 4096 requests its 20 beams return 23 distinct items in
total, 57% of them from the global top-20 — it recites the marginal, and its recall (2.8%) lands just
under popularity (3.93%) for exactly that reason. X-Rec spreads over 3680 items, i.e. it does the
personalisation, but places its candidates poorly inside the right cluster.

That is a statement about *this fixture and this training budget* (1M params, 200 + 300 steps), not about
SID-AR at production scale — the paper's catalog is ~1e9 items, where a SID is shared by many items and
cannot be recited. It is, however, the reason this repo no longer claims "the three ideas work": the
mechanism is verified, the quality claim is not reproduced.

## What this is not

- **Not the official code.** ByteDance has not released X-Rec (verified: no code link in the paper,
  `org:bytedance+xrec` returns zero repos). This is an independent implementation from the equations.
- **Not a reproduction of the paper's numbers.** The fixture is synthetic (6k items, 8 interest modes,
  1M parameters, 200 + 300 steps). The paper runs on a TikTok streaming benchmark with 0.46B params and a
  billion-item catalog. Absolute recall is two orders of magnitude smaller and **not comparable**.
- **Not evidence that X-Rec beats SID-AR.** The control is implemented and it wins on recall for the
  collapse reason above; neither variant is competitive with a popularity baseline here.
- **Not production-grade.** No distributed training, no feature store, single item table held in RAM,
  one process, no auth/TLS on the serving path.
- The real-data path (`dataset.py`) is exercised on a log in MovieLens format, because network egress is
  blocked in the build environment; pointing `--data` at a real `ratings.dat` is a one-flag change.

## The gaps this repo used to list

| gap | status now |
|---|---|
| B1 real dataset + real item vectors | `dataset.py`: ml-1m / ml-100k / CSV parsing, PPMI+SVD item tower, anchors, leave-one-out splits, `--data` flag. Needs a real `ratings.dat` to produce real numbers — see the note under "What this is not" |
| B2 SID-AR entity control | `models_sid.py` + `sid.py`, trained and evaluated end to end; quantiser recon cosine 0.938 (paper 0.94). Result: collapses to the marginal at this scale, documented above |
| B3 >= 3 seeds | `scripts/run_experiments.py`; the table above is mean[min-max] over 3 seeds |
| B4 ANN index | `index.py` IVF: 50k x 128, nlist=256 -> recall@10 97.7% at 0.14 ms/query, 100% at 7.4 ms (exact probe) |
| B5 all-prefix pretraining mask | implemented (`model.py: loss_all_prefix`, one encoder pass, N-1 targets); no measurable gain, reported as such |
| C serving | `serve.py`: checkpoint carries the item table, ANN built at startup, `/health` `/metrics` `/recommend`, plus a self-test that does a real socket round-trip |
